# 模型与计费

模型、倍率、上下文和可用状态看控制台。这里不写死价格表。

## 先测模型

打开 [操练场](https://zzmapi.zzmsgdsg.xyz/console/playground)，选模型，发一句短问题。能回，再去配置软件。

## 查看可用模型

两种方式：

1. 登录控制台查看模型列表、倍率和可用状态。
2. 使用 `/v1/models` 接口测试当前 Key 能访问的模型。

```bash
curl https://zzmapi.zzmsgdsg.xyz/v1/models \
  -H "Authorization: Bearer YOUR_ZZM_API_KEY"
```

## 怎么选

按活儿选：

| 场景 | 选法 |
| --- | --- |
| 普通问答、轻量总结 | 用快一点、便宜一点的模型 |
| 代码、长文档、复杂分析 | 用更强、上下文更大的模型 |
| 批量任务、自动化脚本 | 先用小样本测试，再批量运行 |
| 第三方客户端聊天 | 选稳定、延迟低的模型 |
| 图片生成 | 使用 `gpt-image-2`，先低质量测试再提高质量 |

## 上下文长度

不同模型上下文不同。客户端填得太大，可能超时、截断或失败。

做法：

- 先查看控制台模型说明。
- 对长文档先做分段、摘要或检索。
- 不要把完整历史对话无限追加到每次请求。

## 余额消耗

余额消耗看模型倍率、输入长度、输出长度。实际扣费看控制台。

降低消耗的方法：

- 系统提示词保持简洁。
- 不把无关历史塞进上下文。
- 用更小的模型处理分类、摘要、格式转换等轻任务。
- 批量任务先抽样测试输出质量。

## 为什么不写固定价格表

模型和倍率会变。固定价格表很快过期。以控制台和群公告为准。
