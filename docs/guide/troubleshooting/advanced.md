# 进阶配置与效率优化

这页先放高频建议，后面可以继续扩充。

## 一个工具一个 Key

最省事的做法：

- Claude Code 一个 Key
- Codex 一个 Key

这样出了问题最好排查，也方便单独停用。

## 先做控制台测试，再去改工具

先用 [控制台测试](https://zzmapi.zzmsgdsg.xyz/console/playground) 把模型测通，再去改本地工具配置。

这样能先排掉：

- 余额问题
- 分组问题
- 模型权限问题

## Codex 想稳一点

先检查这几项：

- `base_url` 带 `/v1`
- `wire_api = "responses"`
- `auth.json` 里是当前在用的 Key
- 改完后完全退出再重开 Codex

## Claude Code 想稳一点

先检查这几项：

- `ANTHROPIC_BASE_URL` 不带 `/v1`
- `ANTHROPIC_AUTH_TOKEN` 是当前 Key
- `ANTHROPIC_MODEL` 用控制台当前可用模型

## 用项目说明文档提升效率

如果你常用 Claude Code 或 Codex，建议在项目根目录准备一份项目说明文档，让工具少走弯路。

可以写的内容包括：

- 项目技术栈
- 目录结构
- 约定的代码风格
- 测试方式
- 不能乱改的关键目录

这样能减少重复解释项目背景。

## 常用命令速查

平时最常用的，通常就这些：

- 清理当前会话
- 重新开始一个新上下文
- 查看当前模型或配置
- 退出当前工具

具体命令名称以工具当前版本实际支持为准。

## 扩展能力怎么加

如果后面你需要更复杂的能力，例如：

- 浏览器自动化
- 文档检索
- 项目知识库
- 自定义工作流

可以再往工具里补插件、外接服务或额外配置。先把基础链路配通，再加扩展最稳。

## 排障前先检查什么

如果你不想来回乱改，最先检查这几项：

1. 当前工具用的是哪个 Key
2. 地址有没有带错或漏掉 `/v1`
3. 当前模型在这个分组里有没有权限
4. 控制台测试能不能先跑通
5. 本地工具是不是还缓存着旧配置

## 后续怎么扩展文档

有新工具、新报错或新的控制台入口时，继续补到对应栏目，避免把排障信息分散到旧页面里。
