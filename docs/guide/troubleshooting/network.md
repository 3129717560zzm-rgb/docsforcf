# 网络与连接类问题

连不上时，先查地址，再查网络。

### 地址与工具协议

| 工具 | 正确地址 |
| --- | --- |
| Codex | `https://zzmapi.zzmsgdsg.xyz/v1` |
| Claude Code | `https://zzmapi.zzmsgdsg.xyz` |

### 常见现象

- Claude Code 连不上：先看是不是误加了 `/v1`
- Codex 连不上：先看是不是漏了 `/v1`
- 客户端报 `ECONNREFUSED`、`ENOTFOUND`、超时：先查本地网络和代理

### 先判断是不是账号问题

按这个顺序查：

1. 去控制台测试同一个模型
2. 控制台测试正常，再回头查本地工具
3. 控制台测试也不正常，再看余额、Key、分组

### 先做一个最短测试

```bash
curl https://zzmapi.zzmsgdsg.xyz/v1/models \
  -H "Authorization: Bearer YOUR_KEY"
```

能返回内容，说明域名本身能连。

### `502`、`504`、`524`

先试：

- 减少上下文
- 改短一点的问题先测
- 换模型
- 稍后重试

短请求能恢复时，再继续测试原请求。

### 开了代理也可能出问题

如果你本地挂了代理：

- 先不改 Key
- 先短暂关闭代理试一次
- 再看是代理问题还是地址问题

### 控制台测试正常，客户端不正常

控制台测试正常、本地工具连不上时，查这几项：

- 地址和工具协议不一致
- 本地代理冲突
- 客户端自己拼接了错误路径
- 本地 DNS 或代理节点不稳定
